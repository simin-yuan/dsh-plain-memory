# 我的记忆仓

这是「原味记忆」（dsh-plain-memory）的记忆资产：纯 Markdown，放在你自己的**私有** Git 仓库里。
插件在会话开始拉取、在写完记忆后提交；推送在后台跑，不挡对话。拔掉插件，这个仓库仍然是普通 Markdown，DSH 一点没变。

## 目录

| 路径 | 层 | 放什么 |
|---|---|---|
| `self.md` | 自我 | 身份、偏好、长期约束。只有你明确确认过的内容才会写进来。 |
| `episodic/<日期>-<标题>-<短id>.md` | 情景 | 哪一天做了什么、结论是什么、哪里卡住了。 |
| `semantic/<日期>-<标题>-<短id>.md` | 语义 | 跨会话可复用的事实与方法。 |
| `.state/` | 运行时 | 每个窗口一张状态卡、待确认的自我层提案、健康日志。已被忽略，不进版本库。 |

**一条记忆一个文件**：两个窗口同时写不同记忆时不会互相覆盖；同一天同标题重复写入会覆盖同一个文件，不会堆出重复条目。

## 一条记忆长什么样

```md
### 缓存与注入
- id: semantic-20261113-k3f9a
- date: 2026-11-13
- session: 2026-11-13T10:00:00Z/ab12cd34
- cues: 注入, pre-step, 卡住, 提示缓存
- related: semantic-20261110-x1y2z

pre-step 瀑布里追加 user message，只追加不改前缀，所以提示缓存不失效。
```

`cues` 是线索词：以后你换一种说法提到它，这条记忆会被本地匹配到并注入，最多 3 条，标注为不可信任的背景。
写 `cues` 时想的是「我以后会怎么问」，不是「这条记忆里出现了哪些词」：优先写抽象概念（可复现、降低验证成本、信任、卡住）和口语说法（转圈、换电脑、同时）。

`related` 指向另一条记忆的 `id`，命中时允许再带一跳关联。

## 建议

- 仓库保持**私有**。这里会有你的工作习惯和项目判断。
- 想整理时手动跑一次巩固：读最近的情景记忆，合并重复、解决冲突，再提炼一轮线索词。提示词见插件仓库的 `prompts/daily-consolidate.md`。不做定时任务。
- 想手动改就直接改，提交前看一眼 diff 就行；插件下次拉取会尊重你的改动。
